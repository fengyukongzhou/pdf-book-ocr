# OCR & EPUB 数字化常见踩坑指南 (Troubleshooting Guide)

数字化书籍转写全流程中，以下 5 个高发故障模式曾导致多次排版翻车，必须通过自动化机制与严格规范予以预防：

---

## 1. Pandoc 全局脚注冲突陷阱 (Global Footnote Collision)
- **现象**：Pandoc 在将多个 Markdown 章节同时编译进同一本 EPUB 时，默认将所有的脚注 `[^1]`、`[^2]` 视为**全局命名空间**。如果各章节都从 1 重新起号，后编译章节的同名注释会覆盖前章，导致整本书的脚注链接指向全部错位乱串。
- **解决方案**：
  在章节组装阶段（`chapter_assembler.py`），为每个章节的脚注引用与定义强制注入章节唯一前缀（例如 `[^c01_1]`、`[^c02_1]`），而视觉渲染依然保持各章独立的 1, 2, 3... 优雅连续序号。

---

## 2. 列表语法“缺少空行”导致横向坍塌 (Unspaced List Collapse)
- **现象**：
  在 Markdown 中如果写出：
  ```markdown
  **登场人物**：
  - **富姬**，天守夫人...
  - **龟姬**，来自...
  ```
  Pandoc 和 CommonMark 解析器会判定 `-` 只是上一段落的“懒惰折行（Lazy Continuation）”，导致整个列表失效，所有的列表项被全部压平成一整坨带有 `-` 符号的长句。
- **解决方案**：
  标题或引导句后**必须留有一个完整空行**：
  ```markdown
  **登场人物**：

  - **富姬**，天守夫人...
  - **龟姬**，来自...
  ```

---

## 3. 软换行（双空格）导致对白挤塞与首行缩进断层
- **现象**：
  OCR 转写时如果在台词行末使用行尾双空格软换行（`  \n`）：
  ```markdown
  **角色A**：你好。  
  **角色B**：你也好。  
  ```
  在编译为 EPUB 时，所有人的对话都会被封锁在同一个 `<p>` 标签内，仅用 `<br />` 换行。这导致：
  - 只有首位角色按 `<p>` 规则缩进 2 字符，后续所有人全部顶格 0 缩进；
  - 人物台词之间间距为 0，挤塞在一起，而遇到舞台动作时又突然拉开巨大间距，视觉极其难看。
- **解决方案**：
  每句台词必须是独立自然段（`\n\n` 分隔），行尾严禁出现双空格。由 CSS 控制 `p.dialogue` 的 `margin-bottom: 0.45em`，保证舒适的呼吸感。

---

## 4. 跨页断字与未闭合星号（Unclosed Asterisk across Seams）
- **现象**：
  在物理切分分片时，若切分点恰好落在斜体舞台动作 `*...*` 或黑体 `**...**` 内部，可能导致前一分片尾部未闭合、后一分片头部缺少开符号。这会导致 Pandoc 将接下来整整几页文字全部误判为斜体或粗体。
- **解决方案**：
  1. 切分 PDF 时优先选择自然篇目边界或空白页；
  2. 运行 `seam_auditor.py` 自动扫描分片首尾未配对的 `*` 或 `**`。

---

## 5. EPUB 后处理误伤 `nav.xhtml`
- **现象**：
  某些后处理脚本在清洗 EPUB 内的 XHTML 时，若使用粗暴的全文正则或页面清空逻辑，可能会错误清空或重写 `nav.xhtml`（EPUB 的核心目录导航），导致电子书阅读器解析目录树失败或打不开。
- **解决方案**：
  在后处理遍历文件时，必须显式排除导航文件：
  ```python
  if name.endswith(('.xhtml', '.html')) and not name.endswith('nav.xhtml'):
      ...
  ```

## 6. 切片局部索引导致图片同名覆盖 (Slice-Local Index Image Collision)
- **现象**：
  若在切片提取图片时直接使用切片内局部页码 `p_idx` 命名（如 `fig_p001_01`），会导致每个分片的第 1 页图片都命名为 `fig_p001_01.jpeg`，磁盘上的后分片图片直接覆盖前分片图片，且 Pandoc 编译时会将全书不同位置的插图去重合并为同一张图，造成严重错位与丢失。
- **解决方案**：
  提取图片时必须绑定全书绝对页码 `global_pno = p['start_page'] + p_idx`，强制命名为 `fig_p{global_pno+1:03d}_{img_counter:02d}.ext`，确保全局绝对唯一。

## 7. 随文括号注误转脚注导致跨章悬空 (Inline Note Footnote Dislocation)
- **现象**：
  原书中直接附在段落末尾的括号注（如“（注：……”）若被子智能体擅自转换为 `[^n]` 脚注，并放置在切片末尾，在后续按章节聚合时，正文角标可能属于上一章，而注释定义被切到了下一章，导致 EPUB 阅读器解析不到目标注释，点击后弹出 `(注释文本缺失)`。
- **解决方案**：
  提示词模板严格立规：原书正文中的括号注、随文夹注必须 100% 原样保留在段落内，严禁抽离为跳转脚注；仅版心底部有真实编号印制的底注才允许转为 `[^n]`。

---

## 8. 机械切片映射导致的“第XX章”假章节名 (Slice Chunk vs Semantic Heading)
- **现象**：
  若汇编器按分片编号 `part_01` $\to$ “第01章”进行分组，会生成完全违背原书目结构的虚假章节名。
- **解决方案**：
  汇编器先将所有 `raw_md` 顺序拼接为连续文本流，严格以正文中真实出现的 `## 章节标题` 作为切分边界，动态生成真实的逻辑章节文件。

---

## 9. 跨切片对白与断句接缝治理 (Cross-Slice Dialogue & Sentence Seam Healing)
- **现象**：
  物理切片分割容易切断跨页长自然段、未完结对白或无标点延续句。若机械换行，EPUB 会产生突兀空行与缩进断层；若盲目判断行尾句号，当对白句内含终结符但双引号未闭合时（如前一切片末尾为 `他说：“明天见。`，后一切片开头为 `”然后他头也不回地走了。`），粗暴规则会误判该段已完结而拒绝拼接，造成引号割裂。
- **解决方案**：
  流水线由 `seam_auditor.py` 与 `digitize_book.py` 协同执行出版级接缝仲裁：
  1. **跨切片引号闭环焊接 (`MERGE`)**：探测引号奇偶差值（前切片末行 `“` 多于 `”` 且后切片首行以 `”` 开头），自动跨分片焊合成同一自然段。
  2. **跨切片未完结断句缝合 (`MERGE`)**：探测末尾非终结标点（逗号、顿号、破折号或无标点），自动与后切片自然段连接。
  3. **文本重叠去重 (`MERGE_DEDUP`)**：探测切片重叠字句（如转写重叠），自动剔除重复前缀再平滑拼接。
  4. **可解释审计门禁**：生成 `seam_report.md`，输出全局接口决策表（含尾句/首句对照与处理动作），供快速回溯复核。

---

## 10. 电子书非线性图表强转表格/Mermaid 坍塌陷阱 (Infographic Table/Mermaid Collapse in EPUB)
- **现象**：
  许多数字化任务试图将研报或白皮书中的环形饼图、柱状对比图或双栏宽表强行逆向为 Mermaid 代码块或 Markdown 文本表格。在移动端或主流 EPUB 阅读器（如 Apple Books、微信读书、Kindle）中：
  - **Mermaid 裸代码暴露**：阅读器出于安全与沙箱限制，绝不执行外部 Mermaid.js 脚本，Mermaid 语法直接退化为未渲染的文本乱码；
  - **表格窄屏挤死**：手机与阅读器宽度通常仅 360~600px，多列表格被强行压缩，表头与单元格发生文字纵向换行（如“美元）名义 GDP 占比”垂直折叠），版面彻底崩坏。
- **解决方案**：
  坚持**“文字走数字流，图表走矢量流”**的双轨出版哲学：
  1. **禁止强行转写**：子 Agent 严禁将带图示或宽表的内容逆向为 Markdown 表格或裸 Mermaid；
  2. **300 DPI 无损矢量裁切**：使用 `<!-- FIGURE: page=... bbox=[...] -->` 标定坐标，由后端脚本调用 PyMuPDF 直接从原版 PDF 抽取 300 DPI 纯白底超清图片（`fig_...png`）；
  3. **自适应居中与双击放大**：在 EPUB 与 Obsidian 中以原生图片呈现，既完全保留原书专业设计配色与排版美感，又天然支持移动端自适应居中和手势全屏无级放大。
  4. **紧凑锁边与防吞并正文铁律 (Tight Bounding Rule)**：
     - 裁切图表时**严禁盲目回退到页脚底线**。对于页面上半部只有单张图表的页面，必须以图题为顶部起点（$y_0$），并以数据说明（“注：”、“数据来源”、“数据截至”）为结束点；
     - **正文绝对阻断**：若图表下方紧跟下一个正文自然段落或小节标题（如“（一）海外资产...”），底部界限 $y_1$ 必须**严格截断在正文首行起始坐标上方**（留 6 pt 安全空白），杜绝将正文文字吞入图片导致 EPUB 中出现“图片内有文字、图片外又有一模一样正文”的重复排版 Bug。
